# 玩法深度与可扩展性 · 前瞻设计（考量，非即建）

> 目的：**现在把模型和扩展点留好**，让未来把某些幕从"纯选择"扩成自定义小游戏、加"通关才进下一幕"的闸门、加多结局——都不用返工。本期只做设计与预留，不建具体小游戏。

## 一、层级与"幕"的定位
```
系列(era) → 主角线(视角) → 幕(act) → 幕内(场景/抉择/可选小游戏)
```
- **一条主角线 = 6–10 幕的成长弧线**（幕数是弧线主干，别注水）。
- **每一幕 = 一个可独立"通关"的门控关卡**：达成通关条件（活到史实正解 / 赢下小游戏）→ 显示"本幕通关"过场（史识小结 + 进度存档）→ 解锁下一幕。
- 深度在**幕内**：2–4 个有分量抉择 + 跨幕状态 + 可选 1 个自定义玩法。

## 二、幕内深度设计（可玩性）
1. **抉择**：每幕 2–4 个，其中部分**不立即重合**，而是设跨幕变量、影响后续与结局（真分支感）。
2. **跨幕状态（VAR 贯穿全弧）**：如 `ren`(韩信的忍)、`xin_liu`(与刘邦关系)、`flaw`(致命弱点累积次数)、`zili`(自立倾向)。这是"角色成长可量化"与"多结局"的基础。
3. **多结局**：不止"通关/死亡"二元。按累积状态分叉，如韩信线：忠汉到底→钟室之祸（史实悲剧）｜若"自立倾向"高→蒙冤前的另一种反思结局（反事实照见）。用 `#ending:<id>` 或 clear 变体承载。
4. **可选自定义玩法**：某些标志性幕挂一个小游戏作为通关关卡（见第三节）。
5. **失败即retry**：死亡/失败回到本幕抉择点（画面复位，已实现）。

## 三、自定义玩法扩展点（关键预留）
**机制：ink 把玩法"外包"给 app 的小游戏模块，拿结果回来分叉。** 核心引擎不含玩法逻辑，保持领域无关/可开源。

### 3.1 约定（预留，暂 no-op）
- ink 内用标签 **`#minigame:<id>`**（或 ink `EXTERNAL minigame(id)`）标记一个玩法关卡。
- 核心 `ink-vn-core` 解析到后，**通过回调 `onMiniGame(id, params)` 把控制权交给 app**（与现有 `onBackground`/`onShowCharacter` 同一套 StageCallbacks 风格），并**暂停叙事**等待结果。
- app 的 **`MiniGameRegistry`**（`id → React 组件`）渲染对应小游戏；玩家完成后组件回传结果 `{ cleared: boolean, score?: number, branch?: string }`。
- 结果写回一个 ink 变量（如 `~ mg_result = "win"`），ink 据此 `{ mg_result == "win": ... - else: ... }` 分叉；`cleared=false` 则视为本幕未过关，重来。

### 3.2 与现有架构的契合（零返工）
- 现有引擎已有 **StageCallbacks 回调模式** + **ink 变量/条件/EXTERNAL**——`onMiniGame` 就是再加一个回调，**天然贴合**，不动核心结构。
- `VNEngine` 当收到 minigame 事件时，挂载 `MiniGameRegistry[id]` 组件覆盖在舞台上；组件 resolve 后调用 `runner.resumeMiniGame(result)` 继续。
- **本期只需**：①在 skill 标签表登记 `#minigame:<id>`（预留，未注册的 id 默认 no-op 直接判过，让剧本能先写）；②`onMiniGame` 回调在 `StageCallbacks` 里留一个可选签名；③本文档。具体小游戏与 registry 后续按需建。

### 3.3 候选小游戏（未来，按标志性幕挂）
| 幕 | 小游戏概念 |
|----|-----------|
| 井陉·背水一战 | 布阵/拔旗易帜的轻策略（背水列阵、奇兵拔赵帜） |

> 小游戏须**服务史实与人物**：赢法=史实策略，蛮干=反事实失败，青月点评。

## 四、"通关才进下一幕"的门控
- **模型**：一条线 = 有序幕序列；`幕N` 通关（clear 条件达成）才解锁 `幕N+1`。
- **落地选项**（后续选一）：
  - A. 每幕一个 ink（storyKey `<主角>:act<N>`），storyline 用 `perspectives`/进度记录已通关幕，UI 顺序解锁（类似上古的 chapter=storyline 但加顺序门控）。
  - B. 一条线一个多幕 ink，用 `#actclear:<id>` 标签在幕界插过场 + 存档 checkpoint，一路演下来。
- **推荐**：叙事连贯性优先用 **B**（一线一 ink，幕界插"本幕通关"过场）；若某幕要接重度小游戏或需要独立重玩，该幕单独走 **A**。二者可混用。
- 现有引擎的死亡→retry + clear 已是雏形；加 `#actclear` 过场 + 幕级进度即可，**不改核心**。
