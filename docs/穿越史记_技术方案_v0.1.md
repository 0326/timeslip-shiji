# 穿越·史记 — 产品设计方案

**版本**：v1.0  
**日期**：2026-06-20  
**赛事**：TREA AI 大赛

---

## 一、项目背景与定位

### 1.1 问题陈述

《史记》是中国人共同的文化母本，但对绝大多数人来说，它躺在书架上"读不进、记不住、串不起"——文言门槛高、人物关系乱、事件时间线散。普通人想了解一段历史，往往只能靠刷碎片化短视频，看完是热闹，记住的是错的。

### 1.2 产品定位

一个 Web 端的**沉浸式历史交互叙事游戏**。核心是把《史记》的文献解析成一条条"活的故事线"：用户通过抽卡解锁角色，选择穿越成史记中的某个角色，跟随该角色的视角体验他的人生轨迹与同时期的历史主线；同时配套人物关系图、事件时间轴、势力演变可视化，以及随点随看的原文翻译与情境解读，把"读古文"变成"逛历史"。

> **核心设计原则**：先被游戏吸引，再在游戏过程中学到知识。文言文不是前置门槛，而是通关提示工具。

### 1.3 价值主张

- **教育普惠**：用"角色穿越 + 可视化"大幅降低古籍阅读门槛，让《史记》从"少数人读得懂的典籍"变成"人人能体验的活历史"
- **零成本接触**：一个浏览器就能用，对教育资源不均衡地区的学生尤其友好
- **认知效率**：把"读懂一段历史"从需要查字典、对照注释的数小时，压缩到一次沉浸式体验

## 二、产品定义

### 2.1 产品形态

基于 inkjs 的 Web 端交互叙事游戏，采用响应式设计，优先适配桌面端（大屏可视化体验），同时支持移动端碎片化阅读。

### 2.2 核心体验公式

```
抽卡解锁角色 → 进入角色故事线 → 阅读文言文提示 → 做出历史选择 → 通关解锁全景
```

### 2.3 产品 Slogan

> "选一个角色，亲历一段历史"

## 三、目标用户

| 用户群 | 特征 | 使用场景 | 核心诉求 |
|--------|------|----------|----------|
| 中小学生 | 12-18岁，正在学习历史/语文 | 课后预习复习、假期拓展 | 有趣地学习历史，帮助考试 |
| 历史爱好者 | 18-35岁，对传统文化有兴趣 | 碎片时间、周末深度体验 | 沉浸式体验历史，满足好奇心 |
| 普通大众 | 被文言门槛劝退的成年人 | 通勤、午休、睡前 | 轻松了解历史，有社交谈资 |
| 教师 | 中学历史/语文老师 | 课堂教学、作业布置 | 现成的教学工具，提升课堂趣味 |

## 四、核心玩法循环

```
获取抽卡券 → 抽卡解锁角色 → 进入故事线 → 阅读文言文提示 → 做出历史选择 → 通关解锁全景 → 分享成就
```

### 4.1 关键设计原则

- **角色是入口**：用户先被角色立绘和故事吸引，而非被历史知识吸引
- **文言文是工具**：每小节放出一段文言文作为抉择提示，用户为了"赢"而主动阅读
- **选择必须正确**：每个抉择点有且只有一个符合历史的选择，选错即死亡重来
- **死亡是教学**：死亡后系统提示"如果你注意到原文中……"，形成错题回顾
- **通关解锁全景**：故事线通关后解锁时间轴、关系图、原文典籍等辅助模块

## 六、卡池系统

### 6.1 设计原则

> **核心定位**：卡池是**收藏与解锁机制**，不是付费赌博机制。所有角色均可通过免费途径获取，不存在付费抽卡。卡池的价值在于收藏成就感、社交分享动机和内容节奏控制。

### 6.2 卡池结构

按历史时期分批开放卡池，每个卡池包含该时期的可玩角色：

| 卡池名称 | 包含角色 | 角色数 | 状态 |
|----------|----------|--------|------|
| 楚汉争霸（首发） | 韩信、项羽、张良、刘邦、萧何、范增、樊哙、虞姬 | 8 | 已开放 |
| 春秋战国 | 勾践、伍子胥、荆轲、商鞅、孙膑、廉颇 | 6 | 未开放（灰色剪影） |
| 大汉风云 | 卫青、霍去病、李广、苏武、司马迁 | 5 | 未开放（灰色剪影） |
| 三国群英 | 诸葛亮、曹操、关羽、周瑜、赵云 | 5 | 未开放（灰色剪影） |

### 6.3 抽卡券获取途径

| 途径 | 奖励 | 限制 |
|------|------|------|
| 每日签到 | +1 抽卡券 | 每日1次 |
| 分享成就卡片 | +1 抽卡券 | 每日上限3次 |
| 通关故事线 | +2 抽卡券 | 每章节1次 |
| 阅读完整原文 | +1 抽卡券 | 每篇章1次 |
| 连续签到7天 | +5 抽卡券（额外奖励） | 每周1次 |

### 6.4 记忆碎片机制

- 抽到重复角色时，自动转化为 **1 个记忆碎片**
- 记忆碎片可用于：
  - 兑换指定角色（10 碎片 = 1 个指定角色）
  - 兑换角色限定立绘（5 碎片 = 1 张限定立绘）
  - 兑换头像框/称号等装饰性内容
- 记忆碎片是**长期积累型货币**，给用户"即使运气差也能拿到想要的角色"的保底感

### 6.5 抽卡概率

| 结果 | 概率 | 说明 |
|------|------|------|
| 新角色 | 根据已拥有角色动态调整 | 优先出未拥有的角色，降低重复率 |
| 重复角色 | 转化为 1 记忆碎片 | 所有角色概率均等，无稀有度区分 |
| 保底机制 | 连续 15 抽未出新角色，第 16 抽必出新角色 | 防止极端非酋体验 |

> **关键设计决策**：角色不区分星级/稀有度。所有角色在抽卡界面展示为统一规格卡片，差异仅在于立绘风格和角色身份标签（如"汉初三杰""西楚霸王"）。避免制造"SSR 焦虑"。

## 七、故事系统

### 7.1 故事线结构

每个角色对应一条完整故事线，故事线由若干**章节**组成，每个章节包含若干**小节**。一个小节 = 一个场景叙事 + 一个抉择点。

### 7.2 故事线示例：韩信线

| 章节 | 小节数 | 核心事件 | 对应史记篇章 |
|------|--------|----------|-------------|
| 第一章：胯下之辱 | 3 | 街头受辱、抉择忍或战、忍后离去 | 淮阴侯列传 |
| 第二章：寄食漂母 | 2 | 穷困潦倒、漂母赠食、承诺报恩 | 淮阴侯列传 |
| 第三章：择主而事 | 3 | 投项羽不受重用、转投刘邦、萧何月下追韩信 | 淮阴侯列传 |
| 第四章：登坛拜将 | 2 | 刘邦设坛拜将、韩信论天下大势 | 淮阴侯列传 |
| 第五章：暗度陈仓 | 3 | 明修栈道、暗度陈仓、平定三秦 | 淮阴侯列传 |
| 第六章：十面埋伏 | 3 | 垓下之围、四面楚歌、项羽自刎 | 淮阴侯列传 + 项羽本纪 |
| 第七章：钟室之祸 | 3 | 功高震主、蒯通劝反、被吕后所杀 | 淮阴侯列传 |

### 7.3 抉择点设计规则

- 每个小节末尾设置 **1 个抉择点**
- 每个抉择点提供 **2-3 个选项**
- 只有 **1 个选项符合历史**，其余选项导致死亡/失败
- 死亡后显示死亡结局文案 + 系统提示（指出原文中的关键线索）+ 返回抉择点重来
- 不设置倒计时，给用户充足时间阅读文言文提示

### 7.4 死亡重来机制

```
用户选择错误 → 播放死亡结局动画/文案
              → 系统提示："注意原文中'XXX'一句……"
              → 提供两个按钮：[重新选择] [查看原文]
              → 点击[重新选择]回到该抉择点
              → 点击[查看原文]展开完整原文+译文+解读
```

### 7.5 ink 脚本结构规范

```ink
// 故事线入口
=== hanxin_story ===
-> chapter_1

// 第一章
=== chapter_1 ===
= scene_1
  场景描述文字……
  -> choice_1

= choice_1
  你面临一个抉择：
  * [选项A：描述] -> choice_1_correct
  * [选项B：描述] -> choice_1_death
  * [选项C：描述] -> choice_1_death_2

= choice_1_correct
  正确选择后的叙事……
  ~ progress += 1
  -> scene_2

= choice_1_death
  死亡结局叙事……
  ~ death_count += 1
  【系统提示：注意原文中"……"一句】
  -> choice_1

// 变量定义
VAR progress = 0
VAR death_count = 0
VAR insight = 0
```

## 八、古文解读系统

### 8.1 核心设计

文言文不是前置学习内容，而是**嵌入在抉择点中的提示工具**。用户为了做出正确选择，需要主动阅读文言文提示，从中提取关键信息。

### 8.2 提示展示方式

| 元素 | 说明 |
|------|------|
| 文言文原文 | 精选 1-2 句关键原文，不超过 50 字 |
| 关键词高亮 | 原文中暗示正确答案的词汇用金色高亮 |
| 白话译文 | 点击"译文"按钮展开，默认折叠 |
| 关键词解读 | 鼠标悬停高亮词显示简短注释（如"玉玦：谐音'决'，暗示下决心"） |

### 8.3 提示示例

> **场景**：鸿门宴，范增劝项羽杀刘邦
>
> **📜 文言文提示**：
> "范增**数目**项王，举所佩**玉玦**以示之者三，项王**默然不应**。"
>
> **关键词**：
> - 数目：多次使眼色 → 范增很急
> - 玉玦：谐音"决" → 暗示下决心杀刘邦
> - 默然不应：沉默不回应 → 项羽内心犹豫，不想杀
>
> **系统提示**：注意项羽"默然不应"的态度。如果你是韩信，此时应该____？

### 8.4 完整原文解锁

故事线通关后，解锁该故事线对应的完整史记原文（包含译文和情境解读）。用户可以在"史记全景 → 原文典籍库"中随时查阅。

## 九、成就系统

### 9.1 设计目标

成就系统承担三个功能：记录玩家里程碑、提供社交分享素材、驱动用户探索更多内容。

### 9.2 成就分类

| 类别 | 示例 | 设计意图 |
|------|------|----------|
| 通关成就 | "兵仙降世"（通关韩信线） | 标记核心进度 |
| 选择成就 | "破釜沉舟"（项羽巨鹿之战选对） | 纪念关键抉择 |
| 死亡成就 | "九死一生"（累计死亡10次） | 降低死亡挫败感 |
| 探索成就 | "博闻强识"（阅读10篇原文） | 鼓励深度学习 |
| 收藏成就 | "群英荟萃"（解锁10个角色） | 驱动抽卡收集 |
| 社交成就 | "桃李满天下"（邀请3位好友） | 驱动传播裂变 |
| 隐藏成就 | "史家绝唱"（发现某个彩蛋） | 增加复玩价值 |

### 9.3 分享卡片设计

成就解锁时自动生成分享卡片，包含：

- 成就名称和图标
- 解锁时间
- 相关数据（如通关用时、死亡次数）
- 角色立绘小图
- 二维码（扫码体验）
- Slogan："我在《穿越·史记》中穿越成了韩信"

## 十、进度系统

### 10.1 全局进度

全局进度 = 已解锁故事线数 / 总故事线数。全部解锁即为 100%。

### 10.2 故事线进度

单条故事线进度 = 已通关章节数 / 总章节数。每条故事线独立计算。

### 10.3 阅读进度

记录用户在"史记全景"中阅读过的原文篇章数量。

### 10.4 进度展示

- 首页显示全局进度条
- 角色卡片显示该角色故事线进度
- 成就页面显示各类成就完成度

### 12.3 ink 脚本工作流

```
1. 编剧用 Inky 编辑器编写 .ink 脚本
2. inklecate 编译 .ink → .json
3. 将 .json 放入 public/stories/
4. React 组件通过 useInkEngine Hook 加载并运行
5. 根据 ink 输出渲染 UI（场景、选项、变量）
```

### 12.4 核心 Hook 示例

```typescript
// src/hooks/useInkEngine.ts
import { useState, useEffect, useCallback } from 'react';
import { Story } from 'inkjs';

export const useInkEngine = (storyJson: string) => {
  const [story, setStory] = useState<Story | null>(null);
  const [currentText, setCurrentText] = useState('');
  const [choices, setChoices] = useState<any[]>([]);
  const [variables, setVariables] = useState<Record<string, any>>({});

  useEffect(() => {
    const newStory = new Story(storyJson);
    setStory(newStory);
    continueStory(newStory);
  }, [storyJson]);

  const continueStory = (s: Story) => {
    const textParts: string[] = [];
    while (s.canContinue) {
      textParts.push(s.Continue());
    }
    setCurrentText(textParts.join(''));
    setChoices(s.currentChoices);
    setVariables(s.variablesState);
  };

  const makeChoice = useCallback((choiceIndex: number) => {
    if (!story) return;
    story.ChooseChoiceIndex(choiceIndex);
    continueStory(story);
  }, [story]);

  return { currentText, choices, variables, makeChoice };
};
```

**技术栈升级说明**：
